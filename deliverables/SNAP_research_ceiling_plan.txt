03. MAP FROM THE FIVE CEILINGS TO CONCRETE EVIDENCE

IMPORTANCE. Explain a real decision that changes when covariance is accounted for. Candidate decisions include whether a model improvement exceeds a meaningful margin, how many training replicates are needed, or whether a benchmark aggregate supports a stable ranking. A diagram or anecdote isn't enough. Compare the decision's performance with and without covariance on evaluation data and report error, uncertainty, and cost. A result that covariance rarely changes decisions is still informative if estimated precisely, but doesn't support exaggerated impact.

CLARITY. A reviewer must understand the target quantity, why cross-half products help, the main result, and its largest limitation from the main paper alone. Use consistent terms for runs, configurations, recipes, item groups, and benchmarks. Remove appendix history that obscures the argument while retaining the evidence needed to audit deviations. Improve readability after deciding the final scientific claim, not before.

NOVELTY. Establish exactly what prior methods already do. The identity for covariance of an average and the repeated-measurement construction aren't new. The realistic contribution may be a carefully validated empirical discovery, a documented failure of standard uncertainty practice, or a useful estimation procedure with proven and tested advantages under the specific data constraints. Don't claim novelty from the acronym, an application-specific name, or the number of sensitivity tables.

EMPIRICAL EVIDENCE. Reproduce the baseline, resolve passage dependence, verify matched-run comparisons, calibrate inference under plausible alternatives, repair the proxy, and compare predictive methods with paired uncertainty. The evidence ceiling also requires accessible provenance and a fresh rebuild of the scientific outputs, not just the paper.

GENERAL CONCLUSIONS. Define the population to which each finding applies. A fixed ten-benchmark battery doesn't become representative because it contains many items. Evaluate transfer across genuinely different training populations and benchmark compositions, and quantify uncertainty in that transfer. If evidence remains narrow, the correct endpoint is a narrow conclusion. Broader wording can't compensate for broader data that don't exist.

05. DEFINE THE ESTIMAND BEFORE CHANGING THE METHOD

Task R1 fixes what the estimator is supposed to measure.

Let c denote configuration, r denote run, and j denote benchmark. For half H, the working model is y_H(c,r,j) = mu_H(c,j) + E(c,r,j) + epsilon_H(c,r,j). E is the component of run performance that generalizes across the chosen item populations. epsilon contains item-dependent deviations. The cross-half argument requires zero conditional mean errors and zero relevant cross-half error covariance, including terms across different runs and benchmarks. Run effects must satisfy the assumptions used in the centering calculation.

Write a short estimand specification distinguishing three quantities. First, run variance on this fixed item bank. Second, item-general run covariance under an item-population model. Third, variation over a population of benchmark batteries. These are different targets. Repeated item splits don't automatically identify the third, and grouping passages changes the item sampling design without by itself proving independence.

For fixed weights w, define V_full = w' Sigma_E w and V_diag = sum_j w_j^2 Sigma_E(j,j). Define theta = V_full/V_diag and Lambda = sqrt(theta) only where the relevant quantities are defined. The original equal-weight construction is a special case. State configuration weights too. Pooling equal-weight configuration moments differs from weighting configurations by precision or number of items.

For the original equal benchmark weights, retain r_eff = sum_{j != k} Sigma_E(j,k) / [(K-1) trace(Sigma_E)]. This is an effective covariance coefficient, not a normalized weighted mean correlation. K_eff = K/Lambda^2 is an equal-weight variance-equivalent count at the specified marginal RMS scale. Don't reuse that formula without derivation for arbitrary weights, interpret it as a count of independent knowledge dimensions, or assume it cannot exceed K under negative aggregate covariance.

Predefine how unequal run counts and missing cells are handled. If pooling per-configuration unbiased covariance estimates equally, normalize each by its own R_c-1 before averaging. Pooling raw products over total degrees of freedom changes weighting. Both can be reasonable, but they answer different questions. Don't let missingness silently choose the target.

R1 passes when an independent reader can identify exactly what is random, what is fixed, which population is averaged, and which quantities the reported interval covers.

06. RESOLVE BOOLQ PASSAGE DEPENDENCE

Task R2 is the highest-priority empirical repair. It can alter the main result.

Recover the source passage for every retained BoolQ item through the official dataset version corresponding to the score release. Prefer stable source identifiers. If matching by passage text is necessary, specify normalization explicitly, preserve the raw text hash, and inspect collisions and unmatched cases. Don't use question similarity or row order as an undocumented substitute for passage identity. Report mapping coverage, ambiguous joins, excluded items, unique passage counts, group-size distribution, and examples of join failures without exposing restricted data.

Build splits at the passage level so no passage contributes items to both halves. Use the same assignment for all runs of a configuration and, where item sets match, across compared populations. Balance halves using information available before examining scores. Approximate item-count balance can be desirable, but splitting a large group to achieve exact balance would defeat the purpose.

Choose weighting deliberately. Averaging passage means gives equal passage weights and changes the target relative to averaging questions. If retaining the question-weighted target, derive the estimator for the group assignment and unequal half denominators, including any inclusion-probability weighting or ratio approximation. Don't apply the old equal-half derivation automatically. Simulate the chosen procedure to quantify finite-sample effects of unequal group sizes and content imbalance. A half-specific mean absorbs mean differences, not arbitrary run-by-content interactions.

Run at least these comparisons on the same recoverable item universe: the exact original item split, a new random item split under the new machinery, the passage-group split, and the battery without BoolQ. Keep a matched universe so a difference isn't secretly caused by dropping unmatched items. If matching loses observations, separately quantify the change caused by item restriction and the change caused by grouping.

For every comparison report the BoolQ diagonal, total diagonal sum, aggregate off-diagonal contribution, aggregate standard deviation, Lambda, and paired changes between split procedures. Give configuration or recipe contributions and uncertainty, not only a headline ratio. If grouped splitting reduces a passage-dependent diagonal term, Lambda may move away from one under a restricted diagonal-contamination model. Don't assume that direction in advance because off-diagonal dependence and changed weights can alter it.

Use repeated prespecified group splits to measure assignment sensitivity. An initial proposed budget is 50, followed by a Monte Carlo precision check. Split variation isn't a confidence interval over runs, passages, or recipes by itself. If inference averages over splits, account for that algorithmic randomness consistently within resampling, or explicitly condition on the chosen assignments.

Construct a simulation with known run covariance, passage effects, heterogeneous passage sizes, and question-level errors. Compare original and grouped splitting as passage effects increase. Include a zero-passage-effect control. Verify that grouping fixes the dependence it is designed to address and document what it cannot fix, including dependence across distinct passages or documents.

R2 passes when mappings and no-overlap assertions are verified, weights and target are explicit, the paired empirical change is quantified, and simulations support the implementation. For every run record model architecture, size, data recipe, initialization seed, data-order seed, checkpoint step, tokens seen, total planned training budget, learning-rate schedule and warmup, batch settings, optimizer, tokenizer revision, code revision, precision, hardware where known, and release provenance. Mark unavailable fields as unavailable.

Equal checkpoint steps don't imply equal training histories or equal learning rates. The manuscript reports that auxiliary runs below 1B have shortened schedules and that 92 configurations have different maximum steps. Compare actual training conditions before calling any contrast a seed-only contrast.

Estimate and report the full released-run covariance, the auxiliary-pair contrast where conditions can be matched, and a strictly matched subset if one exists. With two auxiliary runs there is one within-configuration contrast degree of freedom. The estimator must reflect that loss of information, and broad claims need correspondingly honest intervals. Don't claim a significant difference between panels simply because one interval crosses one and another doesn't. Estimate the paired difference where the design permits it.

Use the adjacent-checkpoint experiment as a sensitivity study of observation time. Keep items, scoring implementation, batching, and hardware fixed within that comparison. Evaluate more than one checkpoint pair or configuration if available, predefining the selection. A large checkpoint effect in PolyPythias doesn't numerically establish the effect in DataDecide. Avoid treating multiple nearby checkpoints as independent training runs.

If the release cannot isolate initialization from data order, retain the combined run effect. A genuine decomposition needs a crossed design that changes initialization and data order separately, or an appropriate existing release. New controlled training is optional and expensive, not a prerequisite for a narrowly phrased released-run study. It becomes necessary if the intended claim specifically attributes covariance to initialization or data-order mechanisms.

R4 passes when the labels seed-only, schedule-matched, auxiliary contrast, and released-run variation each correspond to verified design facts. Missing provenance restricts interpretation even if all estimates look stable.

09. VERIFY THE MATHEMATICAL IMPLEMENTATION

Task R5 connects proof, code, and tests. Retain the corrected cross-half identity and explicitly test configuration centering, symmetrization, and degrees-of-freedom factors. Compare a small transparent loop implementation against the optimized implementation on identical synthetic arrays. The two implementations should be written through different algebraic paths and compared numerically.

Required tests include a single positive-variance benchmark with Lambda equal to one, diagonal covariance with population Lambda one, equal marginal variances with known correlation, unequal variances where r_eff differs from mean correlation, valid negative covariance, and deterministic shifts added to both halves. Permuting item order jointly with its metadata must leave results unchanged. Reordering configurations or runs consistently must leave results unchanged. A global positive scaling of all scores leaves Lambda unchanged but scales aggregate deviation. Scaling individual benchmarks changes weights and can change Lambda.

Test zero and negative estimated denominators, negative aggregate moments, undefined correlations, missing replicates, singleton configurations, zero bootstrap standard errors, and inconsistent item sets. Represent undefined values explicitly. Never force a result into the parameter space by clipping without recording the changed estimator and its justification.

Verify that symmetrization yields symmetry but doesn't guarantee positive semidefiniteness. A moment estimate outside the PSD cone can occur in finite samples. Separate raw moment diagnostics from any regularized covariance used for prediction. Report how projection or shrinkage changes the covariance sum, diagonal, and target, and fit tuning parameters without test-set leakage.

For the permutation identity, verify that permuting each trait's run labels jointly across its two halves preserves its diagonal contribution. Independent trait permutations remove expected off-diagonal terms under the specified randomization. A single common permutation across all traits preserves their pairing and can't generate this null. Include the identity transformation in the appropriate uniform sample space. Retain the statement that expected squared ratio can equal one while expected square root need not.

Verify the information-ratio calculation separately from covariance estimation. For Gaussian item margins and an infinitesimal additive shift, the ratio of accuracy noise to margin noise per unit squared local sensitivity is p(1-p)/phi(z)^2, where z = Phi^{-1}(1-p). Its minimum is pi/2, so a proposed lower threshold of 1.4 cannot falsify that model. Derive the local approximation, check the minimum analytically or with a proof supported by numerical checks, and distinguish the plug-in model quantity from measured information in arbitrary margin distributions. If retaining a claim about empirical relative information, test departures from Gaussian margins and finite shifts rather than treating accuracy alone as a measurement of the needed density at zero.

Retain the finite-K variance decomposition without promising an asymptotic floor from bounded variances alone. A limiting floor needs appropriate convergence of average variance and covariance structure. Also verify the diagonal-contamination example, where adding nonnegative diagonal covariance pulls the squared inflation toward one when the denominators are positive. That restricted example is not a general bias bound when contamination also enters off-diagonal terms.

R5 passes through executed property tests and derivations that state their assumptions. Passing synthetic tests doesn't validate the real-data sampling model.

10. REPAIR INTERVAL INFERENCE AND CALIBRATION

Task R6 first reproduces the actual interval implementation. Recover why it fixes the observed denominator during wild resampling, how it studentizes, what finite-cluster factors it uses, which draws it discards, and how it transforms endpoints. Don't silently substitute a more familiar bootstrap and call it a reproduction.

State the stochastic sampling model for inference. If recipes are treated as independent clusters drawn from a wider recipe population, justify that interpretation. The released 25 recipes may be a designed collection. A cluster bootstrap can model uncertainty under assumptions but doesn't make that collection a random representative sample. Distinguish run randomness conditional on configurations from generalization across recipes and model sizes.

Compare plausible candidate procedures on the SAME target. Candidates may include the current wild cluster method, a jointly resampled numerator-and-denominator cluster procedure, or a ratio interval obtained by test inversion when the denominator is uncertain. These are proposed families, not guaranteed solutions. Verify the relevant statistical derivation and authoritative implementation before using a named method. An interval can legitimately be unbounded or disconnected near a denominator boundary. Don't hide that by reporting only convenient finite endpoints.

Design simulation cells that vary nonzero covariance, recipe-level heterogeneity, unequal marginal variances, trace domination like BoolQ, few effective influences, negative or near-zero covariance moments, skewed or heavy-tailed run effects, group-size imbalance, and cross-half dependence. Separate cells satisfying the estimator's model from deliberate violations. Include a documented estimate of the real influence concentration as one scenario, without presenting that fitted scenario as independent confirmation.

Use enough simulated datasets to measure coverage to useful precision. For nominal coverage p and B datasets, Monte Carlo standard error is approximately sqrt[p(1-p)/B]. At p=0.95, B=2,000 gives roughly 0.0049; B=10,000 gives roughly 0.0022. These are planning calculations. Select B based on desired resolution and budget, and report binomial uncertainty on empirical coverage. For broad exploratory grids, a smaller pilot is acceptable if decisive cells receive adequate replication. Don't claim calibration from 200 datasets because the result happens to be close to 0.95.

Record coverage, lower-tail and upper-tail errors separately, interval width, bias, root mean squared error, undefined-estimate rate, unbounded-interval rate, and discarded-draw fraction. A nominal 95% two-sided interval may fail a proposed upper-bound claim if the relevant tail is miscalibrated even when total coverage looks acceptable. Predefine an application-driven tolerance for coverage error and Monte Carlo precision; don't choose the tolerance after seeing the grid.

Use separate simulation seeds for tuning a candidate procedure and evaluating the chosen procedure. Keep all methods in the final comparison, including unsuccessful candidates with concise explanations. Track power or precision under scientifically relevant alternatives, but don't compute observed-effect power as evidence that the completed study was adequate.

Permutation experiments answer a conditional exchangeability question. Independently relabeling runs within each recipe-size cell can destroy cross-size dependence even while preserving cluster membership. Specify which alignments are randomized. Don't treat a permutation reference as coverage evidence for every nonzero population covariance. Use a plus-one Monte Carlo convention where appropriate and document it, rather than interpreting zero sampled exceedances as probability zero.

Recompute jackknife intervals from unrounded data and the intended confidence level. Keep confidence intervals, simulation dispersion bands, prediction intervals, standard errors, and descriptive removal ranges separately labeled. R6 passes when the chosen interval has a defensible target, its code matches the derivation, and its failures across plausible conditions are quantified. If no interval performs adequately, report the limitation and avoid equivalence or upper-bound claims.

11. REPLACE THE UNSTABLE COMPETENCE PROXY

Task R7 addresses the 10^-6 standard-deviation floor that lets WinoGrande dominate the margin proxy by reported factors around 800–38,000. Don't replace that floor with a different arbitrary constant and declare the mechanism repaired.

Start with an audit of the current proxy. Output each benchmark's estimated variance, denominator used, resulting coefficient, contribution to the proxy, and sensitivity to its removal. Plot these by configuration or recipe where possible. Reproduce the dominance before changing the method.

Choose a measurement strategy based on the claim. The preferred descriptive control is per-run loss on a separate text set, scored consistently at the same checkpoint and disjoint from benchmark items. Verify data provenance and possible overlap. This is a separate observable, not automatically a pure measurement of general competence. Independent items reduce shared measurement noise but don't establish causal mediation or remove all confounding.

If such losses are unavailable, evaluate a prespecified regularized proxy using other benchmarks. Candidate designs include a latent-factor measurement model that accounts for noise or training-fold estimates of stable scales with shrinkage. State what identifies the factor, how signs and scale are fixed, and how uncertainty is propagated. Learn transformations, variances, loadings, exclusions, and hyperparameters using training recipes only. Leave the target benchmark out and preserve passage grouping across measurement splits.

Cross-fitting means training a proxy or nuisance estimate without using the evaluation unit whose error is assessed. Merely using the opposite item half doesn't prevent leakage from held-out recipes into tuning. Keep recipe folds and item partitions distinct. Recompute the entire fitted proxy inside uncertainty calculations where required.

Report proxy reliability, stability across folds, benchmark contribution concentration, and uncertainty in adjusted covariance. Examine whether conclusions depend on one shrinkage choice, the treatment of negative moments, or one benchmark. Include an unadjusted baseline. If measurement error attenuates the regression or adjustments share noisy scores with outcomes, describe the direction only where derived or demonstrated.

R7 passes when one trait no longer dominates through an arbitrary numerical artifact and the proxy has a stated measurement interpretation supported by held-out checks. It doesn't pass merely because adjusted Lambda changes little. If no defensible proxy is possible, remove the mechanism claim and retain the failed proxy as a concise limitation or supplementary diagnostic.

12. REDESIGN THE COVARIANCE PREDICTION COMPARISON

Task R8 distinguishes two prediction problems. Conditional correlation prediction supplies held-out marginal run variances to every model and asks whether learned correlations help. End-to-end uncertainty prediction must estimate those marginal variances from information genuinely available at deployment. The first can be scientifically useful, but isn't a substitute for the second and doesn't eliminate the need for replicates.

Freeze folds at the recipe level for recipe-generalization claims. All sizes and runs belonging to a held-out recipe stay out of training. Use nested training-only selection for shrinkage, factor rank, proxy construction, and regularization. The existing five held-out folds share overlapping training sets, so five fold means aren't five independent observations suitable for an automatic t-test.

Compare the original independence, rank-one competence, rank-one-plus-gain, phenotypic plug-in, and full covariance models. Add a simple shrinkage estimator toward the diagonal as a strong baseline, and a low-rank regularized model only if its tuning and complexity can be evaluated fairly. Keep resource budgets comparable. A complicated estimator beating an unstable unregularized full covariance matrix may demonstrate regularization rather than a new covariance principle.

Specify exactly what each method sees at train and test time. The between-configuration correlation plug-in using held-out scores has an information advantage or different information set that must be explicit. Negative held-out variance clipping is not neutral merely because every model receives it. Report unclipped feasibility, clipped inputs, changes to the scored target, and a sensitivity analysis under a justified alternative.

Compute paired losses for the same held-out configurations. Save predictions, targets, and losses rather than only rounded fold means. Report paired differences, uncertainty, and practical effect sizes. Prefer resampling at the independent design unit with the full fitting pipeline rerun when feasible. If bootstrapping duplicated recipe IDs, prevent copies of one original recipe from leaking across train and test partitions. Alternatively derive and justify a valid design-specific procedure. Label any cheaper conditional interval according to the uncertainty it omits.

The observed covariance target is itself noisy and can share estimates with the predicted diagonal. Quantify that issue. Independent run groups for target estimation are preferable where enough runs exist. With only three runs, a fully independent target may be infeasible. Use simulations with known covariance and transparent conditional evaluation rather than pretending noisy target loss is exact population prediction error.

R8 passes when the comparison has no hidden test information, includes credible simple baselines, and quantifies paired differences. If rankings are unresolved, say so. A claimed gain should exceed a prespecified practically meaningful amount with supporting uncertainty, not simply have the smallest fourth decimal place.

13. ESTABLISH PRACTICAL IMPORTANCE THROUGH DECISIONS

Task R9 supplies the strongest route toward the importance ceiling. Pick a concrete deployment decision before evaluating outcomes. For example, assess whether a measured accuracy improvement is large enough to justify changing a training recipe under a fixed replicate budget. Define the minimum useful improvement from the application or present a transparent sensitivity range if no application-specific threshold exists.

Compare independence-based uncertainty, covariance-aware uncertainty, and a direct replicate-based estimate where available. Evaluate interval calibration, false declarations of improvement, abstention rate, ranking stability, and the number of runs needed for a stated precision. Include runtime and data requirements. The comparison must use the same information budget or clearly disclose differences.

For a score difference between model averages, the variance is V_A + V_B - 2 Cov(A,B). The familiar sqrt(2) times aggregate deviation assumes equal variances and independent run errors. If the two models share seeds or data-order randomness, paired covariance matters. If the score averages n independent runs, its run variance changes with n; derive the relevant unequal-n or paired formula rather than copying a single-run expression.

Observed gaps are noisy. The existing count of 455 among 1,500 pairs below a threshold doesn't identify the fraction of true small gaps. Those 1,500 pairs also share models and aren't independent observations. Evaluate reversals on independent run groups or suitable external replicated data. If that isn't possible, present model-based decision calculations and sensitivity to noise assumptions, with no claim to directly observed reversal frequencies.

For an adequacy claim, predefine the largest acceptable error in the independence approximation. If the concern is only underestimating standard deviation, a valid upper bound on Lambda below 1 plus that tolerance can support a scoped one-sided statement under the model. If both underestimation and overestimation matter, define a two-sided equivalence region and use an appropriate validated procedure. Failure to reject Lambda equal to one is neither test. Derive any replicate-budget recommendation from the variance of the actual single-run or multi-run decision, and check it against independent outcomes or calibrated simulation.

14. TEST GAIN AND FORMAT MECHANISMS HONESTLY

Task R10 keeps descriptive association separate from causal attribution. Multiplying margins by a positive number leaves their signs unchanged. Accuracy invariance in that simulator is a construction check, not evidence that real training changes accuracy through no gain mechanism.

Validate simulator choices against observed score distributions, heterogeneity, and the way the actual covariate is measured. Report residual discrepancies instead of declaring a simulator realistic because one average matches. Propagate uncertainty in the estimated gain scale. The shares obtained under selected simulator settings aren't identified causal bounds, and changing settings until a preferred share appears is invalid.

A stronger scoring-scale experiment can apply prespecified transformations to the same saved scores, holding items and runs fixed. Such an intervention tests a scoring mechanism, not a training mechanism. To isolate scoring format from content, evaluate the same underlying content under multiple scoring rules or formats where this is scientifically meaningful. A transformation that changes semantics or answer difficulty cannot be treated as a pure format intervention.

The current within-format association compares different benchmarks, each with one format. Keep that as an association unless a crossed content-by-format design is obtained. A causal account of training gain or competence needs stronger identification, such as controlled interventions and validated measurements. If those resources are unavailable, don't pursue causal wording merely to increase novelty.

R10 passes when every mechanism statement is labeled according to what was manipulated or observed, and the empirical checks can distinguish the proposed explanation from at least one plausible alternative.

15. EVALUATE BENCHMARK COMPOSITION WITHOUT FALSE POPULATION INFERENCE

Task R11 separates weighting, trait count, and content changes. Report fixed equal-benchmark weights as the main baseline, followed by scientifically motivated prespecified alternatives. Standardizing by estimated seed standard deviation changes weights and can exclude traits with nonpositive moments. Treat it as a separate target, not the same average with a cosmetic rescaling.

For each removal analysis report which benchmarks remain, K, weights, trace, off-diagonal sum, Lambda, and aggregate deviation. Comparing K_eff after removal without acknowledging the change in K can exaggerate differences. Use fixed-K subsets or derived references where the scientific question requires them. Don't choose subsets based on the desired inflation.

The current leave-one-benchmark-out ranges are sensitivity summaries. A benchmark jackknife and quadrature addition to a sampling standard error don't produce a valid population interval unless a sampling model and covariance structure justify them. Retain informative removal plots while dropping unsupported uncertainty decompositions. Label illustrative arithmetic as illustrative if there is a compelling reason to keep it.

If generalizing over benchmark batteries, define a sampling frame. Explain which tasks could have been selected, what weights they represent, and why the chosen batteries cover that frame. More items from the same benchmark don't provide new independent benchmark replication. If no sampling frame is defensible, report results for named batteries and avoid a numerical population-wide independence claim.

23. EVIDENCE GATES AND OUTCOME-DEPENDENT DECISIONS

Gate A is baseline credibility. R0 and R5 must pass before numerical discrepancies can be interpreted as science. If the baseline cannot be reproduced, investigate and correct it before adding new claims.

Gate B is measurement validity. R1–R4 must establish the target, grouping, and training conditions sufficiently for the main interpretation. If passage-aware estimates differ substantially, show the paired change and revise the headline. If grouping barely changes estimates with sufficiently precise uncertainty, that supports stability against this measured dependence, not absence of all dependence.

Gate C is inference. R6 must support the uncertainty claims used in conclusions. If denominator instability or influence concentration prevents reliable bounds, stop claiming equivalence or exclusion of a meaningful threshold. A null interval including one doesn't establish adequacy of independence.

Gate D is mechanism and prediction. R7, R8, and R10 determine whether competence, gain, format, and predictive superiority claims survive. If the proxy remains unstable, remove its explanatory role. If a simple shrinkage baseline matches or outperforms the proposed predictor, report that and reposition the contribution. Uncertain rankings must remain uncertain.

Gate E is importance and generalization. R9, R11, and R12 determine what decisions and populations the paper supports. A covariance correction with little practical effect can support a scoped adequacy result if assessed against a prespecified tolerance and valid uncertainty. A large but inconsistent effect supports a conditional warning, not a universal rule.

Gate F is novelty and communication. R13–R17 establish that the supported result adds knowledge, is presented clearly, and can be audited. If the remaining claim is already known and the experiments add little, acknowledge that the current research direction hasn't reached the intended ceiling.

Every gate needs an artifact, an executed or inspected check, and a written consequence. Thresholds such as “substantial,” “adequate,” or “useful” must be operationalized before they decide an outcome. Use application-grounded tolerances and display sensitivity if no single tolerance is defensible. A gate evaluates evidence quality, not whether the hypothesis wins.
